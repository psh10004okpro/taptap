# 다국어

한국어가 기본이자 **폴백**이다. 브라우저 언어가 `ko*` 면 한국어, 그 외에는 영어로 뜨고,
설정 > 언어에서 고른 값이 그보다 우선한다 (`localStorage: taptap-lang`).

## 구조

| 파일 | 역할 |
|---|---|
| `src/core/i18n.ts` | `t(key, 한국어원문, params?)` · 언어 감지/저장/전환 |
| `src/core/locales/en.ts` | 영어 카탈로그 (키가 없으면 한국어 원문이 나온다) |
| `src/core/names.ts` | 게임 데이터(영웅/유물/펫/존…) 이름 접근자 |

## 왜 오버레이인가

`config.ts` 의 게임 데이터는 한국어 원문을 그대로 들고 있고, 다른 언어일 때만 카탈로그가
그 위를 덮는다. 데이터 정의를 키로 바꿔 흩어놓지 않으므로

- 번역이 없는 항목은 자동으로 한국어가 나온다 — **빈 화면이 생기지 않는다**
- 콘텐츠를 늘려도 번역이 늦어질 뿐 게임이 깨지지 않는다
- `lang === 'ko'` 면 조회 자체를 건너뛴다 (기존 동작과 동일)

## 문구를 추가할 때

```ts
// 화면 문구
this.showToast(t('quest.claimed', '퀘스트 보상을 받았습니다!'));

// 치환
t('hud.stage', '{zone} · 스테이지 {n}', { zone: zoneName(zone), n: st.stage })

// 게임 데이터는 접근자 경유 (def.name 직접 사용 금지)
row.name.setText(`${heroName(h)} · ${heroTitle(h)}`);
```
그 뒤 `src/core/locales/en.ts` 에 같은 키를 넣는다. **빠뜨려도 빌드는 통과하고 한국어로
표시된다** — 그래서 영어로 띄워 눈으로 확인하는 것이 유일한 검증이다.

```bash
npm run preview
# 브라우저 언어를 영어로 두거나, 콘솔에서:
#   localStorage.setItem('taptap-lang','en'); location.reload()
```

## 레이아웃

720x1280 고정 캔버스라 **문구 길이가 곧 레이아웃 사고**다. 특히 하단 5탭은 칸당 142px 라
긴 단어가 들어가면 잘린다 (탭 라벨은 4글자 이상이면 자동으로 16px 로 줄어든다).
UI 문구를 바꾸면 두 언어 모두 스크린샷으로 확인할 것.

## 커버 범위

화면에 나오는 문구는 전부 경유한다 — UI 껍데기, 존/몬스터/보스, 영웅(이름·칭호·패시브),
유물, 펫, 스킬(글리프 포함), 스킬트리(계열 탭 포함), 퀘스트, 업적, 장비 슬롯/등급,
보석 팩, 온보딩 5단계, 랭킹·결제 메시지, 시간 포맷, 로컬 랭킹의 가상 경쟁자 이름.

## 아직 한국어만인 곳

- QA 데브 패널(`?dev=1`)과 `core/DevTools.ts` — 개발자용이라 번역하지 않는다.
- 스토어 등록 문구(`store/listing.md`)는 한/영 원고를 따로 관리한다.

## 언어 추가

`Lang` 타입에 코드를 넣고 `locales/<code>.ts` 를 만들어 `initLang` 에 전달한다.
카탈로그가 비어 있어도 동작하므로 번역을 점진적으로 채울 수 있다.
